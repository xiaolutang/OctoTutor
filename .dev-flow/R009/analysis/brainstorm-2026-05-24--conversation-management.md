# 多对话管理

## 结论

- 要做什么：
  - 左侧侧边栏展示对话列表，右侧为对话区（ChatGPT/DeepSeek 风格）
  - 对话自动生成标题（LLM 总结首轮用户消息）
  - 新建对话：用户发第一条消息时才创建，不提前产生空对话
  - 对话列表按最近活跃时间排序，置顶对话固定在顶部
  - 分页加载：首次 20 条，滚动加载更多
  - 置顶功能：最多 5 条，DeepSeek 风格三点菜单交互
  - 菜单操作：重命名、置顶/取消置顶、删除
  - 硬删除，不需要回收站
  - 新建 conversation 数据库表存储元数据（标题、创建时间、置顶状态等）

- 不做什么：
  - 分享对话（DeepSeek 有但不需要）
  - 对话搜索/标签分类
  - 对话导出
  - 软删除/回收站
  - 移动端适配（当前只做桌面端）

- 关键约束：
  - 对话历史仍依赖 LangGraph checkpointer 存储 messages
  - 新建 conversation 表只存元数据，不重复存消息
  - 标题生成用 LLM，需要考虑延迟和成本
  - 置顶上限 5 条，超出时提示用户先取消已有置顶

- 核心场景：
  1. 用户进入 /chat → 左侧看到对话列表（含置顶区）→ 点击某个对话加载历史
  2. 用户点"新建对话" → 右侧清空 → 发消息时自动创建新对话 → LLM 生成标题 → 列表刷新
  3. 用户 hover 对话项 → 出现三点菜单 → 可重命名/置顶/删除
  4. 用户删除对话 → 确认弹窗 → 硬删除 → 列表移除 → 若是当前对话则切到最新对话

- 待确认：无

## 关键讨论

- 标题生成：选择 LLM 生成（更自然）而非截取前 20 字（太粗糙），需接受额外一次 API 调用
- 新建时机：选"首条消息时创建"而非"按钮点击时创建"，避免空对话污染列表
- 交互风格：参考 DeepSeek 三点菜单悬浮气泡，包含重命名/置顶/删除三项操作
- 置顶上限：5 条，平衡便捷性和列表简洁度
