# OctoTutor 智能体教学策略

## 结论

- **要做什么**：
  - 教学策略（参考 ragDemo "小数" + OctoTutor 自有需求）：
    - 类比驱动：用生活场景解释抽象概念，每次至少一个类比
    - 趣味记忆：创造记忆口诀、谐音梗帮助学生记住公式和定理
    - 步骤化叙事：复杂问题分步骤，每步说清"为什么"
    - 启发式引导：先给思路框架再逐步揭示，引导但不完全藏答案
    - 兜底机制：引导 2-3 轮还不懂 → 直接给清晰解释
    - 纠正误解：检测学生理解有误时指出并纠正
    - 知识关联：提示前置/关联知识点
    - 出练习题：根据知识点生成练习巩固
    - 总结回顾：对话中总结关键要点
    - 语气：轻松自然，像朋友聊天
  - 知识来源：教材为主 + 灵活解释（基于教材内容，但可以用自己的话、类比、例子帮助学生理解）
  - 意图识别：课程相关 → 检索教材 + 引导回答；不相关 → 直接拒绝

- **不做什么**：
  - 不回答非课程问题（直接拒绝，不引导回课程）
  - 不使用计算器/网络搜索等外部工具（永远不会加）
  - 不做对话列表 UI
  - 不做 ReAct/tool-calling（教学行为通过 prompt 工程实现，不依赖 Agent 架构）

- **关键约束**：
  - 智能体的"聪明"不在架构上（不需要 ReAct 循环），在 system prompt 的教学策略上
  - StateGraph 是简单条件路由：意图分类 → 课程相关走检索+回答 / 不相关走拒绝
  - 教学行为（引导/纠正/出题/总结）全部通过 prompt 驱动

- **核心场景**：
  - 学生做作业卡住了，遇到不懂的知识点 → 引导思考 → 兜底解释

- **技术含义**：
  - 不需要 ReAct、不需要 tool-calling、不需要多节点循环
  - 需要：好的 system prompt（教学策略）+ 意图分类 + 条件检索 + 消息持久化
  - LangGraph StateGraph 用于编排和持久化，不用于 Agent 决策

## 关键讨论

- 用户最初倾向 ReAct Agent，讨论后发现只有一个工具（文档检索）不需要 ReAct
- 引导式 vs 直接解答：用户选择引导式（像真人老师），但有兜底机制
- 教材依赖度：教材为主 + 灵活解释（不严格限制只能引用原文）
- 外部工具：用户明确表示"后面也不会加"计算器和网络搜索
- 对比 ragDemo 后，采纳其教学策略（类比驱动、趣味记忆、步骤化叙事），但知识来源保持"教材为主+灵活解释"（不采用 ragDemo 的"100% 仅基于教材"限制）
