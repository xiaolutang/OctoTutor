## Implementation Plan

### 1. LLM Judge Prompt 扩展 (backend/app/evaluation/graders/llm_judge.py)

**Prompt 变更**：在 `JUDGE_USER_PROMPT_TEMPLATE` 中追加任务三（Relevance），同时将 `question` 作为新参数传入。

- 新增 Prompt 参数 `{question}`
- 在现有任务一、二之后追加：
  ```
  任务三：相关性评估
  判断学生的回答是否切题，即是否正面回应了原始问题。
  - relevant：回答直接回应了问题的核心
  - partially_relevant：回答与问题相关但未直接回答核心问题，或只回答了部分
  - not_relevant：回答与问题无关或完全偏离主题
  ```
- 输出 JSON 格式扩展：在 `claims` 和 `coverage` 同级新增 `"relevance": "relevant|partially_relevant|not_relevant"`

**JudgeResult dataclass 扩展**：
- 新增字段 `relevance: float`（默认值 0.0）
- 新增字段 `relevance_label: str`（默认值 "not_relevant"）

**judge() 方法签名扩展**：
- 新增参数 `question: str = ""`
- Prompt 模板中追加 `{question}` 占位符

**_parse_response() 解析扩展**：
- 解析 `data.get("relevance", "not_relevant")`
- 映射规则：`"relevant"` -> 1.0, `"partially_relevant"` -> 0.5, `"not_relevant"` -> 0.0
- 未知值 fallback 到 0.0
- JSON 解析失败时的默认 `JudgeResult` 也包含 `relevance=0.0, relevance_label="not_relevant"`

### 2. eval_runner.py 数据模型扩展 (backend/app/evaluation/eval_runner.py)

**FaithfulnessDetail dataclass 扩展**：
- 新增字段 `relevance: float = 0.0`
- 新增字段 `relevance_label: str = "not_relevant"`
- `to_dict()` 方法输出包含 `relevance` 和 `relevance_label`

**FaithfulnessReport dataclass 扩展**：
- 新增字段 `overall_relevance: float = 0.0`
- `to_dict()` 方法输出包含 `overall_relevance`

**_evaluate_faithfulness_item() 方法扩展**：
- 调用 `llm_judge.judge()` 时传入 `question=item.question`
- 将 `judge_result.relevance` 和 `judge_result.relevance_label` 写入 FaithfulnessDetail
- NEGATIVE 条目（filtered 为空时 early return）的 relevance 保持 0.0

**run_faithfulness() 方法扩展**：
- 计算 `overall_relevance`：只对非 NEGATIVE 条目取均值
- 传入 FaithfulnessReport 构造

### 3. 测试文件扩展

**test_llm_judge.py 新增测试**：
- `TestParseResponse` 新增：解析含 `relevance` 字段的响应（三种标签）
- `TestParseResponse` 新增：不含 `relevance` 字段时 fallback 为 0.0 / "not_relevant"
- `TestParseResponse` 新增：无效 relevance 值 fallback 为 0.0
- `TestJudgeMethod` 新增：judge 方法传入 question 参数后返回 relevance + relevance_label

**test_eval_runner_extended.py 新增测试**：
- `TestRunFaithfulness` 新增：FaithfulnessDetail.to_dict() 包含 relevance 和 relevance_label
- `TestRunFaithfulness` 新增：FaithfulnessReport.to_dict() 包含 overall_relevance
- `TestRunFaithfulness` 新增：NEGATIVE 条目 relevance 为 0.0 且不参与 overall_relevance 均值
- 向后兼容：现有测试中的 mock LLM 响应不含 `relevance` 字段，fallback 为 0.0，测试仍通过

## Acceptance Criteria (Negotiated)

1. **Prompt 扩展**：LLM Judge Prompt 包含任务三（Relevance），judge() 接受 question 参数
2. **JudgeResult 包含 Relevance**：LLMJudge.judge() 返回的 JudgeResult 包含 `relevance` (float) + `relevance_label` (str)
3. **解析 fallback**：LLM 返回不含 `relevance` 字段时，fallback 为 `0.0 / "not_relevant"`
4. **FaithfulnessDetail 包含 Relevance**：FaithfulnessDetail 包含 `relevance` + `relevance_label`，to_dict() 输出包含这两个字段
5. **FaithfulnessReport 包含 overall_relevance**：FaithfulnessReport 包含 `overall_relevance`，to_dict() 输出包含此字段
6. **NEGATIVE 条目处理**：NEGATIVE 条目（无检索结果）的 relevance 设为 0.0，不参与 overall_relevance 均值计算
7. **零额外 API 成本**：Relevance 判定合并在现有 LLM Judge 调用中，不增加 API 调用次数
8. **向后兼容**：现有测试全部通过（不含 relevance 字段的 mock 响应 fallback 为 0.0，不影响断言）
9. **新增测试通过**：Relevance 相关单元测试和集成测试全部通过
