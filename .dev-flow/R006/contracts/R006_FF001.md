## 4. 技术规格

### 4.1 api-client.ts 公共 API

```typescript
// 常量
const BASE_URL = '/api';

// 类型
type GetTokenFn = () => Promise<string | null>;

// 导出函数
export function registerGetToken(fn: GetTokenFn): void;
export async function fetchWithAuth(url: string, init?: RequestInit): Promise<Response>;
```

### 4.2 核心逻辑流程

```
fetchWithAuth(url, init):
  1. URL 拼接：url 以 http 开头 → 直接使用；否则 → BASE_URL + url
  2. 获取 token：getTokenFn ? await getTokenFn() : null
  3. 构建 headers：
     - new Headers(init?.headers)
     - token 存在 → headers.set('Authorization', `Bearer ${token}`)
     - 有 body 且无 Content-Type → headers.set('Content-Type', 'application/json')
  4. 发送请求：fetch(fullURL, { ...init, headers })
  5. 401 处理：
     a. headers 有 X-Retry → 不重试 → redirectToLogin()
     b. 调用 refreshAndGetToken()
     c. 新 token → 构建重试 headers（含 X-Retry: true）→ fetch 重试
     d. 无新 token → redirectToLogin()
  6. 非 401 → 直接返回 Response

refreshAndGetToken():
  1. refreshPromise 已存在 → 复用（去重）
  2. 新建 refreshPromise = Promise.race([getTokenFn(), 30s timeout])
  3. finally → refreshPromise = null（无论成功失败）

redirectToLogin():
  - window.dispatchEvent(new CustomEvent('auth:session-expired'))
```

### 4.3 关键设计约束

- **不导入任何 SDK 类**：api-client.ts 不 import AuthService、TokenManager 等，仅通过 `registerGetToken` 回调获取 token
- **返回原生 Response**：不包装返回值，兼容 SSE ReadableStream（response.body.getReader()）
- **BASE_URL = '/api'**：内部硬编码，与现有 `chat/api.ts` 的 `API_BASE` 值一致
- **refreshPromise 去重**：并发 401 时多个请求共享同一个刷新 Promise
- **30s 超时**：refreshAndGetToken 内 Promise.race 防止刷新挂死
- **X-Retry header**：重试请求附加 `X-Retry: true`，防止无限 401 循环
- **auth:session-expired CustomEvent**：通过事件解耦，不直接调用 AuthContext

### 4.4 模块内部状态

```typescript
// 模块级状态（不导出）
let getTokenFn: GetTokenFn | null = null;
let refreshPromise: Promise<string | null> | null = null;
```
