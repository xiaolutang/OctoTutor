# OctoTutor 全功能需求分析与方案设计

## 项目定位

**基于固定高中数学教材的启发式问答助手**

- 学生可以问教材内容的疑问，也可以问具体题目
- AI 不直接给答案，通过启发式引导帮助学生理解
- 知识来源是预设的固定教材内容，不支持教材版本切换和管理
- 只做高中数学

## 技术决策

| 项目 | 决策 |
|------|------|
| 产品形态 | Web 应用 |
| AI 底座 | OpenAI API |
| 登录方式 | 接入自有 SDK |
| 题目输入 | 图片上传 + 文字输入 |
| 教材知识库 | 固定教材内容预录入，无管理后台 |

## 完整功能链路

```
登录 → 进入对话 → 提问（文字/图片） → AI 基于固定教材启发式引导 → 继续追问或结束
```

## 技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 框架 | Next.js 14+ (App Router) | 全栈开发效率高 |
| UI | Tailwind CSS + shadcn/ui | 现代化 UI，开发快 |
| 数学公式 | KaTeX | 轻量、渲染快 |
| AI | OpenAI GPT-4o / Vision | 多模态识别 + 推理 |
| 知识库 | 向量数据库(Pinecone/PGVector) + 结构化数据 | RAG 检索 + 知识点关联 |
| 数据库 | PostgreSQL | 关系型数据 |
| ORM | Prisma | TypeScript 优先 |
| 登录 | 自有 SDK | — |
| 对象存储 | S3 / 阿里云 OSS | 图片存储 |
| 部署 | Vercel + Docker | 前端 Vercel，后端服务 Docker |

| DEC-004 | 对话上下文管理：长对话 token 限制处理策略 | architecture | 是 |
| DEC-005 | 数学公式渲染：KaTeX vs MathJax | tech_choice | 是 |

## 风险

| ID | 风险 | 影响 | 应对 |
|----|------|------|------|
| RSK-001 | AI 数学推理准确率不稳定 | 高 | MVP 先用 GPT-4o，评估 o1/o3 推理模型 |
| RSK-002 | 图片中数学公式识别率不够 | 中 | 支持识别结果手动修正 |
| RSK-003 | 长对话超出上下文窗口 | 中 | 实现上下文压缩策略 |
| RSK-004 | 启发式引导不够"像老师" | 中 | 建立评测集，迭代 prompt |
