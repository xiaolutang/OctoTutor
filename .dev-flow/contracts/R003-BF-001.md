### 变更步骤

#### Step 1: 创建目录结构
- `mkdir -p services/frontend`
- `mkdir -p services/backend`
- `touch services/backend/.gitkeep`

#### Step 2: 迁移前端文件（git mv 保留历史）
使用 `git mv` 逐项迁移：
- `git mv src/ services/frontend/src/`
- `git mv public/ services/frontend/public/`
- `git mv e2e/ services/frontend/e2e/`
- `git mv package.json services/frontend/package.json`
- `git mv package-lock.json services/frontend/package-lock.json`
- `git mv next.config.ts services/frontend/next.config.ts`
- `git mv tsconfig.json services/frontend/tsconfig.json`
- `git mv vitest.config.ts services/frontend/vitest.config.ts`
- `git mv playwright.config.ts services/frontend/playwright.config.ts`
- `git mv postcss.config.mjs services/frontend/postcss.config.mjs`
- `git mv eslint.config.mjs services/frontend/eslint.config.mjs`
- `git mv components.json services/frontend/components.json`
- `git mv next-env.d.ts services/frontend/next-env.d.ts`
- `git mv middleware.ts → services/frontend/src/middleware.ts` (middleware.ts 已在 src/ 下，无需单独迁移)

注意：不迁移以下文件（留在根目录或重新生成）：
- `node_modules/` — 在 services/frontend/ 下重新 `npm install`
- `.next/` — 在 services/frontend/ 下重新 `npm run build`
- `architecture.md` — 保留在根目录
- `README.md` — 保留在根目录
- `evals/` — 保留在根目录（属于项目级别）
- `docs/` — 保留在根目录
- `test-results/` / `test-debug/` — gitignore 的临时目录

#### Step 3: 更新 tsconfig.json 路径别名
`services/frontend/tsconfig.json` 中 `paths` 配置 `"@/*": ["./src/*"]` 在新位置下仍然正确（因为 tsconfig.json 与 src/ 同在 services/frontend/ 下），无需修改。

#### Step 4: 更新 vitest.config.ts 路径别名
`services/frontend/vitest.config.ts` 中 `alias: { "@": path.resolve(__dirname, "./src") }` 在新位置下仍然正确，无需修改。

#### Step 5: 更新 components.json 路径
`services/frontend/components.json` 中 `tailwind.css: "src/app/globals.css"` 和 `aliases` 使用 `@/` 前缀，在新位置下仍然正确，无需修改。

#### Step 6: 更新 package.json
`services/frontend/package.json`:
- `"@xlfoundry/auth-sdk-web": "file:../xlfoundryTest/auth-sdk-web"` — 此路径在 CI/Docker 构建中由 build.sh 处理（临时复制到构建上下文），本地开发路径需更新。但考虑到 build.sh 已将 auth-sdk-web 复制到项目根目录的构建上下文中，Dockerfile 中的路径需要同步更新。
- 其他字段不变。

#### Step 7: 更新 deploy/Dockerfile
当前 Dockerfile 的构建上下文是项目根目录，COPY 指令引用根目录下的文件。迁移后需调整：
- `WORKDIR /build` 不变
- `COPY auth-sdk-web/...` 路径不变（build.sh 从外部复制到根目录）
- `COPY package.json package-lock.json* ./` → 需从 `services/frontend/` 复制
- `RUN sed ...` 不变
- `COPY next.config.ts tsconfig.json ...` → 需从 `services/frontend/` 复制
- `COPY src ./src` → 需从 `services/frontend/src/` 复制
- `COPY public ./public` → 需从 `services/frontend/public/` 复制
- `RUN rm -rf ./src/app/dev` → 路径不变（WORKDIR 内）
- 构建上下文保持项目根目录，Dockerfile 中路径改为 `services/frontend/...`

具体变更：
```dockerfile
# 2. 复制项目 package 文件并安装依赖
COPY services/frontend/package.json services/frontend/package-lock.json* ./

# 3. 复制项目源码
COPY services/frontend/next.config.ts services/frontend/tsconfig.json services/frontend/postcss.config.mjs services/frontend/eslint.config.mjs services/frontend/components.json ./
COPY services/frontend/src ./src
COPY services/frontend/public ./public
```

#### Step 8: 更新 deploy/build.sh
- `BUILD_CONTEXT="$PROJECT_ROOT"` 不变（仍在根目录构建）
- auth-sdk-web 复制目标路径不变
- Dockerfile 路径不变

#### Step 9: 更新 deploy/docker-compose.yml 和 docker-compose.local.yml
- 当前使用预构建镜像 `image: octotutor:latest`，不涉及 build context，无需修改
- 环境变量和 labels 不变

#### Step 10: 更新 .gitignore
根目录 `.gitignore` 需要调整路径：
- `/node_modules` → `/node_modules` + `services/frontend/node_modules`（或保留通用 `node_modules`）
- `/.next/` → `services/frontend/.next/`（或保留通用 `.next/`）
- `/test-results/` → `services/frontend/test-results/`
- `auth-sdk-web/` → 保持不变（build.sh 仍复制到根目录）

推荐改为通用模式（不绑定具体路径）：
```gitignore
node_modules
.next
test-results/
test-debug/
```

#### Step 11: 更新 .dockerignore
当前内容：
```
node_modules
.next
.git
.dev-flow
.env*
deploy
```
需新增：
```
services/backend
```

#### Step 12: 删除根目录残留
迁移完成后，根目录应仅保留：
- `services/`
- `deploy/`
- `.dev-flow/`
- `.gitignore`
- `.dockerignore`
- `README.md`
- `architecture.md`
- `docs/`
- `evals/`

根目录不再有 `src/`, `public/`, `e2e/`, `package.json` 等前端文件。

#### Step 13: 验证
- `cd services/frontend && npm install && npm run build` 成功
- `cd deploy && ./build.sh` 成功构建 Docker 镜像
- Docker 容器启动后 `/dev` 页面功能正常
