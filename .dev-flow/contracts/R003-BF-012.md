## implementation_plan

### 目标
更新 Docker Compose 配置支持前后端双容器部署，验证 Traefik 路由正确：前端 catch-all、后端 /api/* 路由到 FastAPI。

### 前置条件

- R003-BF-002 已完成：FastAPI 后端骨架已搭建，health endpoint 存在
- 前端已有 Dockerfile（deploy/Dockerfile）和 Traefik labels 路由
- 后端已有 Dockerfile（services/backend/Dockerfile）

### 现状分析

#### 当前 docker-compose.yml（生产）
- 仅包含 `octotutor`（前端）服务
- 使用预构建镜像 `octotutor:latest`
- 通过 Traefik labels 路由，绑定域名
- 加入 `gateway` + `auth-network` 网络

#### 当前 docker-compose.local.yml（本地）
- 仅包含 `octotutor`（前端）服务
- 加入 `auth-network-local` 网络
- 域名 `octotutor.localhost`

#### 后端 Dockerfile
- 基于 `python:3.12-slim`
- 安装 requirements.txt
- 复制 `app/` 目录
- 创建数据目录（data/raw, data/parsed 等）
- 暴露端口 8000
- 启动命令 `uvicorn app.main:app --host 0.0.0.0 --port 8000`

### 设计方案

#### 1. 生产 docker-compose.yml 变更
- 重命名 `octotutor` → `octotutor-frontend`（语义更清晰）
- 新增 `octotutor-backend` 服务
- 后端 Traefik 路由规则：`PathPrefix(`/api/`)` 优先级高于前端 catch-all
- 后端需要环境变量：`DASHSCOPE_API_KEY`
- 后端需要 volume 挂载：data 目录持久化
- 后端 health check：`/api/health`

#### 2. 本地 docker-compose.local.yml 变更
- 同样拆分为前后端两个服务
- 后端加入 `auth-network-local`
- 后端域名为 `octotutor-api.localhost`（通过 Traefik 路由）
- 前端仍然通过 Traefik catch-all 路由

#### 3. Traefik 路由规则设计
```
前端: Host(`octotutor.localhost`) → octotutor-frontend:3000（catch-all）
后端: Host(`octotutor.localhost`) && PathPrefix(`/api/`) → octotutor-backend:8000（优先匹配）
```
- 使用 Traefik priority 确保后端路由优先于前端
- 前端 Next.js rewrites 不变（已有 /api proxy 逻辑不需要，Traefik 层面已处理）

#### 4. 资源约束（4核4GB 服务器）
- 后端 memory limit: 1GB（ChromaDB 嵌入式 + Python）
- 前端 memory limit: 512MB（Node.js standalone）
- 后端 deploy.resources.limits.memory: 1024M
- 前端 deploy.resources.limits.memory: 512M

#### 5. build.sh 更新
- 新增后端镜像构建功能
- 构建两个镜像：`octotutor-frontend:latest` 和 `octotutor-backend:latest`

### Traefik Labels 设计

#### 生产环境
**前端**:
```yaml
- "traefik.http.routers.octotutor-frontend.rule=Host(`${OCTOTUTOR_DOMAIN}`)"
- "traefik.http.routers.octotutor-frontend.priority=1"  # 低优先级，catch-all
- "traefik.http.routers.octotutor-frontend.entrypoints=websecure"
- "traefik.http.routers.octotutor-frontend.tls=true"
- "traefik.http.services.octotutor-frontend-svc.loadbalancer.server.port=3000"
```

**后端**:
```yaml
- "traefik.http.routers.octotutor-backend.rule=Host(`${OCTOTUTOR_DOMAIN}`) && PathPrefix(`/api/`)"
- "traefik.http.routers.octotutor-backend.priority=10"  # 高优先级
- "traefik.http.routers.octotutor-backend.entrypoints=websecure"
- "traefik.http.routers.octotutor-backend.tls=true"
- "traefik.http.services.octotutor-backend-svc.loadbalancer.server.port=8000"
```

#### 本地环境
**前端**:
```yaml
- "traefik.http.routers.octotutor-frontend-local.rule=Host(`octotutor.localhost`)"
- "traefik.http.routers.octotutor-frontend-local.priority=1"
- "traefik.http.routers.octotutor-frontend-local.entrypoints=web"
```

**后端**:
```yaml
- "traefik.http.routers.octotutor-backend-local.rule=Host(`octotutor.localhost`) && PathPrefix(`/api/`)"
- "traefik.http.routers.octotutor-backend-local.priority=10"
- "traefik.http.routers.octotutor-backend-local.entrypoints=web"
```

## risk_negotiation

| 风险标签 | 风险描述 | 缓解措施 |
|---------|---------|---------|
| config | Docker Compose 配置复杂度增加 | 分层配置：生产用预构建镜像，本地用 build context |

## contract_alignment

### 与架构文档对齐
- 前后端分离部署：Traefik 网关路由，前端 Next.js + 后端 FastAPI 独立容器
- Backend API 是检索能力唯一入口，Frontend 不直接访问 ChromaDB
- ChromaDB 嵌入式运行在后端容器内，不独立部署
- DashScope API 调用统一在 Backend 内，Frontend 不持有 Key

### 与现有部署流程对齐
- 生产环境使用预构建镜像（image: 字段），build.sh 负责本地构建
- 本地开发复用 xlfoundryTest 的 Traefik + auth-center 网络
- Traefik labels 方式配置路由，与现有方式一致
