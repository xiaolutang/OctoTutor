### Step 2. 新增 _retrieve() 私有方法

**文件**: `backend/app/chat/service.py`

在 `_rrf_fuse()` 静态方法之前，新增 `_retrieve()` 实例方法：

```python
def _retrieve(self, question: str, top_k: int) -> RetrieveResult:
    """抽取检索管线：Embed → Vector → Threshold → BM25 → RRF → Rerank → Truncate

    Args:
        question: 用户问题
        top_k: 检索数量（保留参数，实际使用 settings.retrieval_top_k）

    Returns:
        RetrieveResult: 检索结果 + 降级状态
    """
    embedding = self._embedding.embed_query(question)
    vector_results = self._vector_store.query(embedding, self._settings.retrieval_top_k)

    # 相似度阈值过滤
    vector_results = [
        r for r in vector_results if r.score >= self._settings.similarity_threshold
    ]

    # BM25 检索 + RRF 融合
    if self._settings.bm25_enabled:
        bm25_results = self._bm25.query(question, self._settings.retrieval_top_k)
        fused = self._rrf_fuse(vector_results, bm25_results, self._settings.rrf_k)
    else:
        fused = vector_results

    if not fused:
        return RetrieveResult(chunks=[])

    # Rerank 精炼（失败降级，不抛异常）
    degraded = False
    degradation_reason = None
    try:
        reranked = self._reranker.rerank(question, fused, self._settings.rerank_top_n)
        if not reranked:
            reranked = fused[: self._settings.rerank_top_n]
            degraded = True
            degradation_reason = "rerank_empty"
    except Exception:
        reranked = fused[: self._settings.rerank_top_n]
        degraded = True
        degradation_reason = "rerank_failed"

    # 字符数截断保护
    context_chunks = self._truncate_by_chars(
        reranked, self._settings.chat_max_context_tokens
    )

    return RetrieveResult(
        chunks=context_chunks,
        degraded=degraded,
        degradation_reason=degradation_reason,
    )
```

**要点**：
- 检索逻辑完全从 handle_chat 原样搬出，零行为变更
- 空检索返回 `RetrieveResult(chunks=[])`，由调用方决定行为
- Reranker 异常被内部捕获，降级返回 `degraded=True`
- 降级逻辑与原 handle_chat 完全一致（rerank_empty / rerank_failed）
- 保留 `_rrf_fuse` 和 `_truncate_by_chars` 不变

### Step 3. 重构 handle_chat()

**文件**: `backend/app/chat/service.py`

将现有 handle_chat 方法替换为调用 `_retrieve()`：

```python
def handle_chat(self, question: str, top_k: int) -> ChatResponse | None:
    result = self._retrieve(question, top_k)
    if not result.chunks:
        return None
    answer, sources = self._generator.generate(question, result.chunks)
    return ChatResponse(
        answer=answer,
        sources=sources,
        context_used=len(result.chunks),
        degraded=result.degraded,
        degradation_reason=result.degradation_reason,
    )
```

**要点**：
- 返回类型添加 `| None` 注解（原代码 return None 但未标注）
- 空检索 return None — 保持 R004 契约不变，Router 层仍负责 raise 404
- `degraded` 和 `degradation_reason` 从 `_retrieve()` 的 RetrieveResult 获取
- 原有 `context_used` 字段从 `len(context_chunks)` 改为 `len(result.chunks)`
- Router 层（router.py）零改动，仍判断 `result is None` → 404

### Step 4. 新增 stream_chat() 异步方法

**文件**: `backend/app/chat/service.py`

在 handle_chat 之后、`_rrf_fuse` 之前新增：

```python
async def stream_chat(
    self, question: str, top_k: int
) -> AsyncIterator[StreamEvent]:
    """异步流式对话方法

    按阶段 yield SSE 事件：
    - 正常流程：status(retrieving) → sources? → status(generating) → token×N → done
    - 检索异常：status(retrieving) → error
    - 空检索：status(retrieving) → status(generating) → token×N → done（无 sources）
    - LLM 异常：... → error

    Args:
        question: 用户问题
        top_k: 检索数量

    Yields:
        StreamEvent: SSE 流式事件
    """
    # ── 阶段 1：检索 ──
    yield StreamEvent(
        type="status",
        data=StatusPayload(stage="retrieving", message="正在检索教材..."),
    )

    try:
        result = await asyncio.to_thread(self._retrieve, question, top_k)
    except Exception as e:
        # 仅 Embedding / VectorStore 失败走 error path
        # Reranker 失败已被 _retrieve() 内部降级，不触发此处
        if "embedding" in str(e).lower() or "dashscope" in str(e).lower():
            yield StreamEvent(
                type="error", data=make_error(ChatErrorCode.EMBEDDING_FAILED)
            )
        else:
            yield StreamEvent(
                type="error", data=make_error(ChatErrorCode.VECTOR_STORE_ERROR)
            )
        return

    context_chunks = result.chunks  # 可能为空，stream_chat 使用 LLM 兜底

    # ── 检索结果处理 ──
    if context_chunks:
        sources = [
            SourceReference(
                chunk_id=chunk.chunk_id,
                book=chunk.metadata.book,
                section=chunk.metadata.section,
                page_start=chunk.metadata.page_start,
                page_end=chunk.metadata.page_end,
            )
            for chunk in context_chunks
        ]
        yield StreamEvent(type="sources", data=sources)
    # 无结果：不发 sources event，LLM 使用数学判断模式兜底

    # ── 阶段 2：生成 ──
    yield StreamEvent(
        type="status",
        data=StatusPayload(stage="generating", message="正在生成回答..."),
    )

    try:
        has_token = False
        async for token in self._generator.generate_stream(question, context_chunks):
            has_token = True
            yield StreamEvent(type="token", data=token)

        if not has_token:
            yield StreamEvent(
                type="error", data=make_error(ChatErrorCode.LLM_EMPTY_RESPONSE)
            )
            return

        yield StreamEvent(type="done", data=None)

    except ConnectionError:
        yield StreamEvent(
            type="error", data=make_error(ChatErrorCode.LLM_CONNECT_FAILED)
        )
    except TimeoutError:
        yield StreamEvent(
            type="error", data=make_error(ChatErrorCode.LLM_TIMEOUT)
        )
    except Exception:
        yield StreamEvent(
            type="error", data=make_error(ChatErrorCode.LLM_STREAM_ERROR)
        )
```

**要点**：
- `_retrieve()` 通过 `asyncio.to_thread` 在线程池中执行，不阻塞事件循环
- 检索异常区分 Embedding（EMBEDDING_FAILED）和 VectorStore（VECTOR_STORE_ERROR）
- 有检索结果时 yield sources event（SourceReference 列表）
- 空 chunks 时不 yield sources event，LLM 进入数学判断模式（generate_stream 内部处理）
- LLM 生成使用 BB001 提供的 `generate_stream()` 方法
- LLM 空响应（has_token=False）yield LLM_EMPTY_RESPONSE error
- LLM 异常按类型映射：ConnectionError → LLM_CONNECT_FAILED、TimeoutError → LLM_TIMEOUT、其他 → LLM_STREAM_ERROR
- RateLimitError 在 analysis 中提到但当前 OpenAI SDK 的 RateLimitError 继承自 Exception，可通过 catch-all 捕获；若需单独处理可后续迭代

## Acceptance Criteria (Negotiated)

1. **_retrieve() 签名**：`def _retrieve(self, question: str, top_k: int) -> RetrieveResult`，返回携带 chunks/degraded/degradation_reason 的 RetrieveResult
2. **_retrieve() 行为等价**：检索逻辑从 handle_chat 原样搬出，零行为变更；原有 _rrf_fuse 和 _truncate_by_chars 不变
3. **_retrieve() Reranker 降级**：Reranker 异常时返回 `degraded=True` + `degradation_reason="rerank_failed"`，不抛异常
4. **_retrieve() 空检索**：fused 为空时返回 `RetrieveResult(chunks=[])`，由调用方决定行为
5. **handle_chat 重构**：改为调用 `_retrieve()`，空 chunks 时 return None（R004 契约不变）；返回类型添加 `| None` 注解
6. **handle_chat R004 契约**：空检索返回 None，Router 层仍 raise 404；有检索结果时 ChatResponse 携带 degraded/degradation_reason
7. **stream_chat() 签名**：`async def stream_chat(self, question: str, top_k: int) -> AsyncIterator[StreamEvent]`
8. **stream_chat 检索阶段**：`_retrieve()` 通过 `asyncio.to_thread` 在线程池执行；检索异常 yield error event（区分 EMBEDDING_FAILED / VECTOR_STORE_ERROR）后 return
9. **stream_chat 正常流程事件序列**：status(retrieving) → sources? → status(generating) → token×N → done
10. **stream_chat 空检索**：无 sources event，LLM 进入数学判断模式（generate_stream 空 chunks → MATH_JUDGE_PROMPT），token 正常 yield
11. **stream_chat LLM 空响应**：has_token=False 时 yield error(LLM_EMPTY_RESPONSE) 后 return
12. **stream_chat LLM 异常映射**：ConnectionError → LLM_CONNECT_FAILED、TimeoutError → LLM_TIMEOUT、其他 → LLM_STREAM_ERROR
13. **import 无报错**：新增的 asyncio/AsyncIterator/StreamEvent/StatusPayload/ChatErrorCode/make_error 均可正常 import
14. **单元测试通过**：6 组单元测试全部通过
15. **现有功能不受影响**：handle_chat 的 R004 契约不变，Router 层零改动

## Negotiated Risks

| ID | Risk | Mitigation |
|----|------|-----------|
| RSK-BB002-01 | _retrieve() 从 handle_chat 抽取时遗漏逻辑导致行为回归 | _retrieve() 检索逻辑与原 handle_chat 逐行对照，单元测试验证空检索返回 None；reranker 降级逻辑完全保留 |
| RSK-BB002-02 | asyncio.to_thread 与同步组件（DashScope Embedding、ChromaDB）的线程安全性 | ChromaDB 客户端和 DashScope SDK 均为线程安全（只读操作），to_thread 线程池默认大小足够 |
| RSK-BB002-03 | 检索异常字符串匹配（"embedding"/"dashscope"）依赖第三方错误消息格式 | 匹配逻辑作为 heuristic 使用，未匹配时走 VECTOR_STORE_ERROR 兜底，不会遗漏；未来可改为异常类型匹配 |
| RSK-BB002-04 | OpenAI SDK RateLimitError 未单独捕获（被 Exception catch-all 覆盖） | 当前映射为 LLM_STREAM_ERROR，action 均为 "retry"，用户可见行为一致；后续迭代可细化错误码 |
