### Step 3. 新增 generate_stream() 异步流式方法

**文件**: `backend/app/infra/llm.py`

在 `generate()` 方法之后、`_build_numbered_context()` 之前，新增：
```python
async def generate_stream(
    self, query: str, context_chunks: list[QueryResult]
) -> AsyncIterator[str]:
    """异步流式生成回答

    使用 AsyncOpenAI 的 stream 模式逐 token yield，
    通过 async with 上下文管理器确保 Stream 资源释放。

    Args:
        query: 学生问题
        context_chunks: 检索到的相关教材片段（空列表则进入数学判断模式）

    Yields:
        逐个 token 字符串
    """
    if context_chunks:
        context_text = self._build_numbered_context(context_chunks)
        messages = [
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": f"参考教材内容：\n{context_text}\n\n学生问题：{query}"},
        ]
    else:
        messages = [
            {"role": "system", "content": MATH_JUDGE_PROMPT},
            {"role": "user", "content": query},
        ]

    stream = await self._async_client.chat.completions.create(
        model=self._model, messages=messages, stream=True
    )
    async with stream:
        async for chunk in stream:
            token = chunk.choices[0].delta.content or ""
            if token:
                yield token
```

**要点**：
- 返回类型 `AsyncIterator[str]`，每个 yield 是一个非空 token 字符串
- `async with stream` 确保 stream 资源在正常/异常情况下均被释放（OpenAI SDK >= 1.0）
- `chunk.choices[0].delta.content` 可能为 None（如 role-only chunk），用 `or ""` 过滤后只 yield 非空 token
- 空 `context_chunks` 进入数学判断模式，使用 MATH_JUDGE_PROMPT 而非 SYSTEM_PROMPT
- 有 `context_chunks` 时复用 `_build_numbered_context()` 构建 context
- messages 构建逻辑与 `generate()` 保持一致

```python
class TestGenerateStreamResourceCleanup:
    def test_stream_released_on_exception(self):
        """异常时 async with 仍调用 __aexit__ 释放资源"""
        async def run():
            with patch("app.infra.llm.AsyncOpenAI"):
                gen = LLMGenerator(api_key="k", base_url="http://x", model="m")
                mock_stream = AsyncMock()
                mock_stream.__aenter__ = AsyncMock(return_value=mock_stream)
                mock_stream.__aexit__ = AsyncMock(return_value=False)

                # 第一个 chunk 正常，第二个 chunk 抛异常
                async def broken_iter():
                    mock_chunk = MagicMock()
                    mock_chunk.choices = [MagicMock()]
                    mock_chunk.choices[0].delta.content = "部分"
                    yield mock_chunk
                    raise RuntimeError("模拟网络断开")

                mock_stream.__aiter__ = lambda self: broken_iter()
                gen._async_client.chat.completions.create = AsyncMock(return_value=mock_stream)

                with pytest.raises(RuntimeError):
                    async for _ in gen.generate_stream("问题", []):
                        pass

                # 验证 __aexit__ 被调用
                mock_stream.__aexit__.assert_called_once()

        asyncio.run(run())
```

## Acceptance Criteria (Negotiated)

1. **AsyncOpenAI 客户端初始化**：LLMGenerator.__init__ 同时创建 `self._client` (sync) 和 `self._async_client` (AsyncOpenAI)，两者使用相同 api_key/base_url
2. **原有方法零改动**：`generate()` 和 `_build_numbered_context()` 的签名、行为、import 路径均不变；现有 `test_llm_generator.py` 全部通过
3. **generate_stream() 签名**：`async def generate_stream(self, query: str, context_chunks: list[QueryResult]) -> AsyncIterator[str]`
4. **有 chunks 流式输出**：传入非空 context_chunks 时，使用 SYSTEM_PROMPT + `_build_numbered_context()` 构建 messages，逐个 yield 非空 token
5. **空 chunks 数学判断**：传入空 context_chunks 时，使用 MATH_JUDGE_PROMPT 作为 system prompt，user message 为纯 query（无 context 前缀）
6. **资源释放保证**：`async with stream` 确保在正常完成和异常情况下 stream 资源均被释放
7. **MATH_JUDGE_PROMPT 常量**：可在 `app.infra.llm` 中 import，内容与方案设计一致
8. **import 无报错**：`from app.infra.llm import LLMGenerator, SYSTEM_PROMPT, MATH_JUDGE_PROMPT` 可成功 import
9. **单元测试通过**：3 组测试（token yield、空 chunks prompt、异常资源释放）全部通过
