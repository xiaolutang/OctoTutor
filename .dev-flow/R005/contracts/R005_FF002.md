## Implementation Plan

### Step 1. use-chat-stream.ts — SSE 通信 hook

**文件**: `frontend/src/chat/use-chat-stream.ts`（新建）

导出两个成员：
- `chatStreamFetch(question, callbacks, abortController, onSetStreaming)` — 核心流式请求逻辑（纯副作用函数，exported for testing）
- `useChatStream()` — React hook，返回 `{ sendMessage, stop, isStreaming }`

核心逻辑：
1. `fetch POST /api/chat/stream` 发送 `{ question, top_k: 10 }`
2. 读取 ReadableStream，使用 `parseSSEEvents` 解析 SSE 事件
3. 按 event.type 分发回调：status → onStatus, sources → onSources, token → onToken, done → onDone, error → onError
4. 错误分类：
   - 首事件前失败 → `onError({ code: '00000', ... })`
   - 首事件后中断 → `onError({ code: '00001', ... })`
   - AbortError → 不触发 onError（用户主动停止）
5. AbortController 管理：sendMessage 创建新实例存入 abortRef，stop() 调用 abortRef.abort()
6. finally 中清理 isStreaming 和 abortRef

设计决策：将核心逻辑提取为 `chatStreamFetch` 纯函数，避免测试需要 `@testing-library/react` 依赖（contract 约束不新增 npm 包）。

### Step 2. use-chat-stream.test.ts — 单元测试（5 个用例）

**文件**: `frontend/src/__tests__/chat/use-chat-stream.test.ts`（新建）

1. **SSE 事件按序回调**：mock SSE 流，验证 onStatus → onSources → onToken → onDone 按序触发
2. **HTTP 非 200**：mock 返回 `{ ok: false, status: 500 }` → onError({ code: '00000' })
3. **首事件后流中断**：使用 pull 模式 ReadableStream，第一次读取成功后第二次报错 → onError({ code: '00001' })
4. **首事件前网络异常**：mock fetch reject → onError({ code: '00000' })
5. **AbortController stop**：abort 后 fetch reject DOMException(AbortError) → onError 不触发

Mock 策略：
- `vi.stubGlobal('fetch', fetchSpy)` mock 全局 fetch
- `mockFetchSSE()` 辅助函数构建 ReadableStream
- 直接测试 `chatStreamFetch` 函数（不依赖 React renderer）
