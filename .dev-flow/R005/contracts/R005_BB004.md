## Implementation Plan

### Step 1. 环境就绪检查

**前置条件验证脚本**：

```bash
#!/bin/bash
# 检查 Docker 环境就绪状态

set -euo pipefail

echo "=== BB004 环境就绪检查 ==="

# 1. 检查 Docker 是否运行
if ! docker info &>/dev/null; then
    echo "[BLOCKED] Docker 未运行"
    exit 1
fi
echo "[OK] Docker 正在运行"

# 2. 检查 auth-network-local 是否存在
if ! docker network inspect auth-network-local &>/dev/null; then
    echo "[BLOCKED] auth-network-local 网络不存在"
    echo "  请先启动: cd ~/project/xlfoundryTest && ./deploy/deploy.sh local"
    exit 1
fi
echo "[OK] auth-network-local 网络存在"

# 3. 检查 auth-center 是否健康
HEALTH=$(docker inspect --format='{{.State.Health.Status}}' auth-center 2>/dev/null || echo "unknown")
if [[ "$HEALTH" != "healthy" ]]; then
    echo "[BLOCKED] auth-center 未运行或不健康 (状态: $HEALTH)"
    exit 1
fi
echo "[OK] auth-center 健康"

# 4. 检查 API 凭证
if [[ -z "${DASHSCOPE_API_KEY:-}" ]]; then
    # 检查 .env 文件
    if [[ -f ".env" ]] && grep -q "DASHSCOPE_API_KEY" ".env"; then
        echo "[OK] DASHSCOPE_API_KEY 在 .env 文件中"
    else
        echo "[BLOCKED] DASHSCOPE_API_KEY 未配置"
        exit 1
    fi
else
    echo "[OK] DASHSCOPE_API_KEY 已设置"
fi

# 5. 检查 curl 是否可用
if ! command -v curl &>/dev/null; then
    echo "[BLOCKED] curl 未安装"
    exit 1
fi
echo "[OK] curl 可用"

echo ""
echo "=== 环境就绪，可以开始部署 ==="
```

**要点**：
- 5 项前置检查，任一失败则任务 blocked
- 明确输出错误信息和修复建议
- 此步骤失败不产生代码变更

```bash
while [[ $ELAPSED -lt $MAX_WAIT ]]; do
```

#### 3.1 测试 #1 — 正常流程完整事件序列

```bash
echo "=== 测试 #1: 正常流程 ==="

RESPONSE=$(curl -s -N http://octotutor.localhost/api/chat/stream \
    -H "Content-Type: application/json" \
    -d '{"question": "什么是集合？", "top_k": 10}' \
    --max-time 30)

# 验证 status(retrieving) 事件
echo "$RESPONSE" | grep -q "event: status" || { echo "[FAIL] 缺少 status 事件"; exit 1; }
echo "$RESPONSE" | grep -q '"stage": "retrieving"' || { echo "[FAIL] 缺少 retrieving 状态"; exit 1; }

# 验证 sources 事件
echo "$RESPONSE" | grep -q "event: sources" || { echo "[FAIL] 缺少 sources 事件"; exit 1; }

# 验证 status(generating) 事件
echo "$RESPONSE" | grep -q '"stage": "generating"' || { echo "[FAIL] 缺少 generating 状态"; exit 1; }

# 验证 token 事件
echo "$RESPONSE" | grep -q "event: token" || { echo "[FAIL] 缺少 token 事件"; exit 1; }

# 验证 done 事件
echo "$RESPONSE" | grep -q "event: done" || { echo "[FAIL] 缺少 done 事件"; exit 1; }

# 验证事件顺序：status → sources → status → token → done
# 提取事件类型序列
EVENT_SEQUENCE=$(echo "$RESPONSE" | grep "^event:" | sed 's/event: //' | tr '\n' ',')
echo "事件序列: $EVENT_SEQUENCE"

# 验证以 status 开头，以 done 结尾
[[ "$EVENT_SEQUENCE" == status* ]] || { echo "[FAIL] 事件序列未以 status 开头"; exit 1; }
[[ "$EVENT_SEQUENCE" == *done,* ]] || { echo "[FAIL] 事件序列未以 done 结尾"; exit 1; }

echo "[OK] 测试 #1 通过"
```

#### 3.4 测试 #4 — SSE 格式验证

```bash
echo "=== 测试 #4: SSE 格式 ==="

RESPONSE=$(curl -s -N http://octotutor.localhost/api/chat/stream \
    -H "Content-Type: application/json" \
    -d '{"question": "什么是函数？", "top_k": 10}' \

# 验证 Content-Type
CONTENT_TYPE=$(curl -s -I -X POST http://octotutor.localhost/api/chat/stream \
    -H "Content-Type: application/json" \
    -d '{"question": "test", "top_k": 10}' \
    | grep -i "content-type" || echo "")

[[ "$CONTENT_TYPE" == *"text/event-stream"* ]] || { echo "[WARN] Content-Type 非 text/event-stream（可能是 Traefik 代理行为）"; }

# 验证 SSE 事件格式：event: {type}\ndata: {json}\n\n
# 提取 event 行

DATA_LINES=$(echo "$RESPONSE" | grep "^data:")

[[ -n "$EVENT_LINES" ]] || { echo "[FAIL] 未找到 event: 行"; exit 1; }
[[ -n "$DATA_LINES" ]] || { echo "[FAIL] 未找到 data: 行"; exit 1; }

# 验证 data 为有效 JSON（检查 status 事件的 data）
echo "$RESPONSE" | grep "^data:" | head -1 | sed 's/^data: //' | python3 -c "import sys,json; json.load(sys.stdin)" \
    || { echo "[FAIL] data 字段非有效 JSON"; exit 1; }

echo "[OK] 测试 #4 通过"
```

#### 3.5 测试 #5 — 来源数据完整性

```bash
echo "=== 测试 #5: 来源数据完整性 ==="

RESPONSE=$(curl -s -N http://octotutor.localhost/api/chat/stream \
    -H "Content-Type: application/json" \
    -d '{"question": "什么是集合？", "top_k": 10}' \
    --max-time 30)

# 提取 sources 事件的 data
SOURCES_DATA=$(echo "$RESPONSE" | awk '/^event: sources/{found=1} found && /^data:/{print; found=0}' | sed 's/^data: //')

if [[ -n "$SOURCES_DATA" ]]; then
    # 验证 JSON 结构
    echo "$SOURCES_DATA" | python3 -c "
import sys, json
sources = json.loads(sys.stdin.read())
assert isinstance(sources, list), 'sources 应为列表'
if sources:
    s = sources[0]
    required = ['book', 'section', 'page_start', 'page_end']
    for field in required:
        assert field in s, f'缺少字段: {field}'
    print(f'[OK] sources 包含 {len(sources)} 条记录，字段完整')
else:
    print('[WARN] sources 为空列表（可能是检索无结果）')
" || { echo "[FAIL] sources 数据格式验证失败"; exit 1; }
else
    echo "[WARN] 未找到 sources 事件（可能是检索无结果）"
fi

echo "[OK] 测试 #5 通过"
```

## Acceptance Criteria (Negotiated)

### 硬性通过项（全部必须通过）

1. **环境就绪**：deploy/deploy.sh local --backend-only 构建成功，Docker 容器启动
2. **健康检查**：GET /api/health 返回 `{"status": "healthy", "chromadb": {"connected": true, ...}}`
3. **正常流程完整事件序列**：POST /api/chat/stream 返回 `status(retrieving) → sources → status(generating) → token×N → done`，事件顺序正确，以 status 开头、以 done 结尾
4. **检索无结果 + LLM 兜底**：输入无匹配问题，无 sources event，有 token event（LLM 兜底），有 done event
5. **断线检测**：SSE 连接中途中断后，后端日志无 unhandled error 堆栈（Traceback）
6. **SSE 格式正确**：每个事件格式为 `event: {type}\ndata: {json}\n\n`，data 字段为有效 JSON
7. **来源数据完整**：sources event 的每条记录包含 `book`、`section`、`page_start`、`page_end` 字段
8. **非流式回归**：POST /api/chat 有结果返回 200，无结果返回 404

### 观察项（不阻断，记录即可）

9. **LLM 故障/超时场景**：依赖真实 LLM 状态，可能无法稳定复现，记录为观察项
10. **Reranker 降级场景**：观察 sources 事件中是否携带 `degraded` 字段（依赖真实 Reranker 状态）
11. **Content-Type**：Traefik 代理后 Content-Type 可能为 `text/event-stream` 或 `application/octet-stream`，记录实际值

### 降级策略

12. **环境不可用降级**：如果 Step 1 环境检查失败（Docker 未运行 / auth-center 未启动 / API 凭证缺失），任务标记为 `blocked`，不阻断后续前端任务（FF002/FB001 可独立进行）
13. **部分测试失败降级**：硬性项 #1-#2（部署+健康）失败 → blocked；#3-#8 任一失败 → 记录失败详情，标记为 `needs_investigation`，开发者手动排查
