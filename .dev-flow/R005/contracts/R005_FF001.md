### Step 2. parse-sse.ts — SSE 文本解析纯函数

**文件**: `frontend/src/chat/parse-sse.ts`（新建）

```typescript
export interface SSEEvent {
  type: string;
  data: any;
}

export function parseSSEEvents(chunk: string, remaining: string): { events: SSEEvent[]; remaining: string } {
  const buffer = remaining + chunk;
  const parts = buffer.split('\n\n');
  const events: SSEEvent[] = [];
  const newRemaining = parts.pop() || ''; // 最后一个可能不完整，留作下次

  for (const part of parts) {
    if (!part.trim()) continue;
    let type = '';
    let data = '';
    for (const line of part.split('\n')) {
      if (line.startsWith('event: ')) type = line.slice(7);
      else if (line.startsWith('data: ')) data = line.slice(6);
    }
    if (type) {
      events.push({ type, data: data === 'null' ? null : JSON.parse(data) });
    }
  }
  return { events, remaining: newRemaining };
}
```

**要点**：
- 纯函数，无副作用，不依赖任何外部状态
- 签名 `parseSSEEvents(chunk, remaining)` — 函数内部拼接 buffer，调用方只需传入新 chunk 和上次 remaining
- 按 `\n\n` 分割事件块，`parts.pop()` 取出最后一段（可能不完整）作为新 remaining
- `data === 'null'` 时返回 null（处理 `done` 事件的 `data: null`）
- 其他 data 值走 `JSON.parse` 解析；如果 JSON.parse 失败，说明 SSE 格式异常（由调用方兜底）

**Negotiation Note — 函数签名差异**：
analysis 文档（第 1301 行）签名是 `parseSSEEvents(buffer: string)`，调用方自己管理 buffer 拼接。方案设计签名是 `parseSSEEvents(chunk, remaining)`，函数内部拼接。Contract 采用方案设计签名，理由：(1) 更符合 SSE 流式场景的 chunk-by-chunk 语义；(2) 调用方不需要自己做 `buffer += chunk` 拼接。FF002 调用方式为：
```typescript
// FF002 useChatStream 中的调用
const { events, remaining } = parseSSEEvents(chunkText, bufferRef.current);
bufferRef.current = remaining;
```

### Step 4. use-chat-storage.ts — localStorage 读写封装

**文件**: `frontend/src/chat/use-chat-storage.ts`（新建）

```typescript
import { Message } from './types';

const STORAGE_KEY = 'octotutor-chat-messages';

export function loadMessages(): Message[] {
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    if (!raw) return [];
    return JSON.parse(raw);
  } catch {
    return [];  // 数据损坏时静默恢复为空
  }
}

export function saveMessages(messages: Message[]): void {
  try {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(messages));
  } catch {
    // 静默失败（localStorage 满或隐私模式）
  }
}
```

**要点**：
- 导出两个纯函数 `loadMessages()` 和 `saveMessages()`，不使用 React hook 形式
- `loadMessages()`：无数据返回 `[]`，JSON.parse 失败（数据损坏）返回 `[]`，静默恢复
- `saveMessages()`：写入失败静默忽略（localStorage 配额满或隐私模式限制）
- STORAGE_KEY 为 `'octotutor-chat-messages'`，与 R005 localStorage 方案一致（DEC-chatui-005）
- FB001 的 ChatUI 组件直接调用这两个函数（不通过 hook 间接层）

**Negotiation Note — 函数 vs Hook**：
analysis 文档（第 1336 行）使用 `function useChatStorage()` hook 形式返回 `{ loadMessages, saveMessages }`。方案设计导出两个独立函数。Contract 采用方案设计的独立函数形式，理由：(1) loadMessages 需要在 useEffect 中调用，不需要 hook 上下文；(2) saveMessages 需要在多处回调中调用（done/stopped/error），hook 形式会引入不必要的闭包复杂性；(3) 两者都不依赖 React 状态，纯函数更简单。

### Step 5. 单元测试

**文件**: `frontend/src/__tests__/chat/parse-sse.test.ts`（新建）

测试覆盖 4 个维度：

1. **完整事件解析**：输入 `"event: status\ndata: {\"stage\":\"retrieving\",\"message\":\"正在检索...\"}\n\n"` + remaining `""` → 返回 events 数组含 1 个事件 `{ type: 'status', data: { stage: 'retrieving', message: '正在检索...' } }`，remaining 为 `""`

3. **多事件合并解析**：输入 `"event: status\ndata: {...}\n\nevent: token\ndata: \"hello\"\n\n"` → 返回 2 个事件
4. **data=null 处理**：输入 `"event: done\ndata: null\n\n"` → 返回事件 `{ type: 'done', data: null }`
